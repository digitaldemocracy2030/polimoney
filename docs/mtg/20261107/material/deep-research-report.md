## エグゼクティブサマリー

### 最重要ファインディング 5つ

1. **政治資金の専用クラウド会計ソフトは現在市場に確認されていない**
   - 唯一あった「政治資金クラウド」（ドットジェイピーが freee をベースにカスタマイズ、2018年末リリース）は2021年7月に利用者不足で撤退 [D6][D7]。2026年11月時点の調査では同種の競合は確認されておらず、Ledger は先行者優位を取れる可能性が高い（ただし参入障壁・導入可能性の追加調査が必要）

2. **地方議員の政治資金を構造化・可視化しているサービスは存在しない**
   - 政治資金DB.com [D1] → 国政のみ。地方拡充は予定だが未実施
   - 政治資金センター [D2] → PDF アーカイブ中心
   - 47都道府県すべてPDF公開。CSV/Excelはゼロ [T3]

3. **「収支報告書」は3種類あり、現行[README](../../../../README.md)では混同されている**
   - 政治資金収支報告書（政治資金規正法 [S6]）
   - 選挙運動費用収支報告書（公職選挙法 [S5]）
   - 政務活動費の収支報告書（地方自治法）→ これは Polimoney でカバーするか要議論

4. **marumie（チームみらい）はアプローチが根本的に異なるプロジェクト**
   - チームみらいの開発者から「コンセプトもアプローチも違うのでライバルではない」と明言されている
   - marumie [D3] は商業用マネーフォワードを入力IFに利用 / Polimoney は政治資金特化の Ledger を開発
   - marumie は政党・団体・議員ごとに個別公開（四半期更新）/ Polimoney は Hub に集約してAPI公開（リアルタイム対応可能）

5. **台湾 g0v モデルが Polimoney に最も近い成功事例**
   - 政府PDFを市民テックがスクレイピング→構造化→可視化するパイプライン [I1]
   - California Civic Data Coalition [I2] のオープンソースデータパイプラインも参考になる

## 1. 地方選管のPDF公開実態

### 1-1. 公開フォーマット

| 形式 | 割合 | 詳細 |
|------|:----:|------|
| **スキャン画像PDF** | 大多数 | 紙提出→スキャン。テキスト検索・コピー不可。手書きも多い |
| **テキストPDF** | 少数 | 総務省ソフトで作成されたもの。ただし選管が再スキャンするケースも |
| **CSV/Excel/JSON** | **0** | 機械判読可能な形式で公開している選管は **1つも存在しない** [T3] |

### 1-2. サイト構造の類型

| パターン | 特徴 | 該当例 |
|---------|------|--------|
| 静的HTMLリスト型 | PDFリンクを羅列。スクレイピングは比較的容易 | 東京、神奈川、福岡、埼玉、千葉 等 |
| 50音/頭文字索引型 | 団体名の頭文字で分類 | 兵庫、京都 等 |
| 年別インデックス型 | 年ごとにページ分割 | 北海道、大阪、愛知 等 |
| JS動的展開型 | スクレイピング困難 | 一部の自治体 |

### 1-3. 機械処理の難易度

| 工程 | 難易度 | 理由 |
|------|:------:|------|
| PDF ダウンロード | 🟡 中 | 47都道府県ごとに個別スクレイパーが必要 |
| PDF → テキスト | 🔴 高 | スキャン画像+手書き。専用OCRのチューニング必須 |
| 構造化データ抽出 | 🔴 高 | 記入方法が団体ごとに異なる |
| 継続的な更新 | 🟡 中 | 3年で消えるため定期クロール必須 |
| 正確性の担保 | 🔴 高 | OCR誤認識、金額の整合性チェックが必要 |

### 1-4. 段階的アプローチの提案

```text
Phase 1: 大都市圏（東京・大阪・愛知・神奈川・埼玉・千葉・福岡・北海道）
  → 静的HTMLリスト型、スクレイピング比較的容易、人口カバー率高

Phase 2: フォーマットが似ている都道府県をグルーピングして横展開

Phase 3: JS動的展開型など困難な自治体を個別対応

Phase 4: Ledger普及 → 入力時点で構造化 → スクレイピング不要に
```

## 2. 地方議員の会計実態

### 2-1. 会計処理の現状

| 方法 | 割合（推定） | 詳細 |
|------|:-----------:|------|
| **手書き** | 多 | 選管のPDF用紙を印刷して黒ボールペンで記入。特に町村議 |
| **Excel** | 最多 | 選管提供のExcelテンプレートまたは総務省ソフトの出力 |
| **総務省デスクトップソフト** | 少 | UIが古く不評。エラー原因特定困難 |
| **クラウド会計ソフト** | ごく少数 | freee等を使う議員はほぼいない |

### 2-2. 既存ツールの競合マップ

| ツール | 対象 | 種別 | 状態 |
|--------|------|------|------|
| 総務省「会計帳簿・収支報告書等作成ソフト」 | 政治資金 | デスクトップ（無料） | 現行。UIが古い [S2] |
| **政治資金クラウド**（ドットジェイピー+freee） | 政治資金 | SaaS（freeeをベースにカスタマイズ） | **2021年7月撤退**（利用者不足）[D6][D7] |
| **セムカン** | **政務活動費のみ** | SaaS（月1,400〜2,200円） | 全国自治体で導入進む [D5] |
| **Seimu View** | 政務活動費 | SaaS | B2G（自治体向け） |
| **Polimoney Ledger** | 政治資金 | SaaS（予定） | **2026年11月時点で同種の競合は未確認** |

> **結論: 2026年11月時点の調査では、政治資金専用のクラウド会計ソフトは競合が確認されていない。ただし参入障壁は低いため、先行者優位の確立が重要**

### 2-3. 地方議員の困りごと Top 8

1. **ワンオペ問題** — 28,000人超の市区町村議員の大半にスタッフがいない
2. **独自の簿記ルール** — 商業簿記と異なる科目分類。企業会計の知識が使えない
3. **領収書管理の膨大さ** — 1年分の領収書を1円単位で突合
4. **法改正への追従** — 度重なる改正で最新ルールのキャッチアップが困難
5. **記載ミスへの恐怖** — 意図的でなくても不記載は罰則・報道リスク
6. **時期的集中** — 提出期限（3月末）が最繁忙期と重なる
7. **二重管理の負荷** — 政務活動費と政治資金の別会計を同時管理
8. **総務省ソフトの使いにくさ** — UIが古い、エラー不明、データ移行が面倒

### 2-4. Ledger の最有望ターゲット

| セグメント | 人数（推定） | 刺さる理由 |
|-----------|:-----------:|-----------|
| **初当選の若手市議** | — | 会計の仕組みがわからず困っている。ITリテラシー高め |
| **無所属議員** | **約19,500人** | 政党のバックオフィスサポートなし。自力で全てやる必要 |
| **女性議員（増加傾向）** | — | 新規参入者が多く、既存のやり方に固執しない |
| **「透明化」を掲げる改革派** | — | Polimoney との親和性が最も高い |

### 2-5. 価格感

| 議員層 | 月額報酬 | 許容価格帯 |
|--------|:-------:|:---------:|
| 町村議 | 約21万円 | 月500〜1,000円が限界 |
| 一般市議 | 約40万円 | 月1,000〜2,000円 |
| 政令市議 | 約75〜95万円 | 月2,000〜3,000円 |

→ **フリーミアム（基本無料＋プレミアム有料）が最適**

### 2-6. 過去の失敗からの教訓

> ドットジェイピーの「政治資金クラウド」が撤退した理由: **「持続的な運用に必要な数の利用政治団体を募ることができなかった」** [D6]
>
> ※ freee をベースにカスタマイズしたサービス（2018年末リリース → 2021年7月終了）。Google インパクトチャレンジの助成を活用。

- 地方議員はITリテラシーが必ずしも高くない → **徹底的なUXの簡素化**
- 議員は保守的で新しいツールの導入に慎重 → **既存の議員ネットワーク・議員研修会等でのチャネル開拓**
- 選管の書式が都道府県ごとに微妙に異なる → **47都道府県の書式対応**

## 4. 競合詳細分析

### 4-1. ポジショニングマップ

```text
                    政治家が入力（供給側）
                           ↑
                           |
           Ledger ●        | ● marumie
           (政治資金特化)   |    (MoneyForward連携)
                           |
    外部から ←─────────────┼─────────────→ Hub集約
    データ化                |              + API公開
                           |
    政治資金DB ●           | ● Polimoney
    政治資金センター ●     |
                           |
                           ↓
                    外部がデータ化（可視化側）
```

> **marumie とは「異なるアプローチの並走プロジェクト」** — チームみらいの開発者からも「コンセプトもアプローチも違うのでライバルではない」と明言されている

### 4-2. marumie とのアーキテクチャ比較

| 項目 | Polimoney | marumie（チームみらい） |
|------|-----------|----------------------|
| **ポジショニング** | 中立的シビックテック（DD2030） | 特定政党（チームみらい）のツール |
| **入力インターフェース** | **政治資金特化の Ledger**（目的特化型） | **マネーフォワード**（商業用ソフト） |
| **技術スタック** | Next.js / Supabase / TypeScript | Next.js v16 / Supabase / TypeScript / Prisma |
| **ライセンス** | AGPL | AGPL |
| **データ公開方式** | **Hub に集約 → 集計・比較・API公開** | **政党・団体・議員ごとに個別公開** |
| **更新頻度** | Ledger 経由で**リアルタイム対応可能** | **四半期更新**（少なくともチームみらい） |
| **データソース** | 外部PDF（Hub）+ Ledger 入力の両輪 | 政治家自身が入力（自発的公開） |
| **カバー範囲** | 全政治家（理論上） | チームみらい所属議員のみ |
| **可視化** | サンキー図 | サンキー図 + B/S + 月次推移 |
| **API** | **Hub にて API 公開予定** | **なし** |
| **寄付機能** | STEP3 で計画 | なし |

### 4-3. Polimoney の独自の価値

| 価値軸 | 内容 |
|---------|------|
| **目的特化型の入力システム** | 商業用ソフトの転用ではなく、政治資金に特化した Ledger を自前で開発 |
| **3プロダクト体制** | 可視化(Polimoney) + データ基盤(Hub) + 入力(Ledger) のエコシステム |
| **地方議員特化** | 国政は2027年1月施行の改正政治資金規正法でオンライン提出義務化・DB公開が予定されている（追加検討は2027年9月まで継続）。**地方約31,500人のデータを構造化する唯一のプラットフォーム** [S1][T1] |
| **外部データ + 自発的データの両輪** | PDFスクレイピング（Hub）と Ledger 入力の両方でデータを確保 |
| **API提供（Hub）** | ジャーナリスト・研究者向けのオープンデータAPI。集計・比較が容易 |

## 5. 法的制約と収支報告書の整理

### 5-1. 収支報告書3種類の比較

| | 政治資金収支報告書 | 選挙運動費用収支報告書 | 政務活動費収支報告書 |
|---|---|---|---|
| **根拠法** | 政治資金規正法 [S6] | 公職選挙法 [S5] | 地方自治法 + 各自治体条例 |
| **対象者** | 政治団体 | 選挙候補者 | 地方議員・会派 |
| **内容** | 政治活動全般の収支 | 選挙運動の収支 | 政務活動費（公金）の使途 |
| **対象期間** | 1〜12月（暦年） | 選挙期間前後 | 4〜翌3月（年度） |
| **提出先** | 総務大臣 or 都道府県選管 | 選管 | 議会の議長 |
| **提出期限** | 翌年3月末 | 第1回: 投票日から15日以内、以後の収支は発生日から7日以内に追加報告 | 条例による（概ね5月末） |
| **公開期間** | 3年（政党交付金は5年） | 3年 | 条例による（概ね5年） |
| **Polimoney 対応** | ✅ メインスコープ | ✅ 対応済み（`/election/`） | ❓ 要議論 |

> **議論ポイント**: 政務活動費を Polimoney のスコープに含めるか？
> - **含める利点**: 地方議員の「お金」を一元的に見える化できる。Ledger で一元管理するなら自然
> - **含めない理由**: 別の法律・別の提出先。セムカン等の既存ツールとの棲み分け
> - **妥協案**: Polimoney（可視化側）では政務活動費も表示するが、Ledger は政治資金のみ管理

### 5-2. 法的リスクのまとめ

| 項目 | リスク | 対策 |
|------|:------:|------|
| データの二次利用 | 🟢 低〜🟡 中 | 著作権法第13条で法令・告示・通達等は対象外だが、行政公開の全PDFが自動的に対象外とは限らない。資料ごとに著作権・利用条件・第三者著作物の有無を確認。出典明記を徹底 |
| スクレイピング | 🟡 中 | サーバー負荷に注意。robots.txt遵守、適切な間隔 |
| OCR誤認識→名誉毀損 | 🟡 中 | 整合性チェック + 免責事項表示（既にフッターに対応済み） |
| 個人情報（寄付者名） | 🟡 中 | 表示方針の明確化、オプトアウト対応方針の策定 |
| 寄付機能（STEP3） | 🔴 高 | 政治資金規正法 [S6] の各種要件＋決済代行業の許認可＋PCI DSS対応が必要 |

## 6. アクションプランへの反映提案

### 反映すべき新規情報

1. **問題リストに追加**: 「収支報告書3種類の混同」問題
2. **スコアリング更新**: marumie とはアプローチが異なることを踏まえた独自価値の再評価
3. **アプローチ更新**: 台湾g0v・California CCDC のデータパイプラインOSS化モデル
4. **機能追加案**:
   - 多層UI設計（30秒ダッシュボード / 探索ビュー / 詳細ビュー）
   - 地理的マップビュー（寄付の地域分布）

5. **Ledger戦略**:
   - フリーミアム価格モデル（基本無料 + 月500〜2,000円のプレミアム）
   - 初当選若手市議・無所属議員（19,500人）を初期ターゲット
   - ドットジェイピーの失敗を教訓にUX簡素化・チャネル開拓を重視
6. **政務活動費の扱い**: 表示はするが管理は別ツール、の妥協案を検討
7. **47選管対応**: Phase 1 で大都市圏8都道府県から着手
