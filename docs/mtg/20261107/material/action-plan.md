# 11/7 会議準備 アクションプラン

> [!IMPORTANT]
> **会議の目的**: メンバー各自が「問題 → アプローチ → 機能」を持ち寄り、Polimoney プロジェクト全体の方向性を確定する。
>
> **前回の合意事項（10/31メモより）**:
>
> - Polimoney は「コミュニケーションチャネル」ではない
> - 事実ベースで計算・表示する **情報源**
> - 意見やその交換の場ではない
> - 政治関連の資金の問題を **直接解決するのではなく**、問題を **実感したり発見できる場** をつくる
> - ライト層 → 政治に興味をもつきっかけ / ヘビー層 → データ活用の情報源

---

## 準備ステップ全体像

```text
STEP 1: 問題をリスト化する
    ↓
STEP 2: 「Polimoney が取り組むべき問題」を選ぶ
    ↓
STEP 3: 各問題へのアプローチを考える
    ↓
STEP 4: アプローチを実現する機能を考える
    ↓
STEP 5: 整合性を検証し、持ち寄り資料にまとめる
```

---

## STEP 1: 問題をリスト化する

### やること

政治に関するお金の「問題」を、**立場を変えながら**網羅的に洗い出す。
以下のフレームで分類し、各問題に **1行の説明** をつける。

> [!IMPORTANT]
>
> ### 前提: 国政 vs 地方の制度変更（2027年1月〜）
>
> 2024年改正政治資金規正法により、**2027年1月以降**、以下が変わる:
>
> | 対象                                                       | オンライン提出 |   データベース公開    |
> | ---------------------------------------------------------- | :------------: | :-------------------: |
> | **国会議員関係政治団体**（政党本部・政治資金団体含む）     |   **義務化**   |  **総務省がDB公開**   |
> | **地方議員の政治団体**（都道府県議・市区町村議の後援会等） | **任意のまま** | **なし（PDFのまま）** |
>
> 出典: 総務省「政治資金規正法の改正に関するお知らせ」（https://www.soumu.go.jp/senkyo/seiji_s/naruhodo/）
>
> つまり **国政のデータアクセス問題は制度的に大幅改善される** 一方、
> **地方（約31,500人・全議員の9割以上）は取り残される**。
> （議員数の出典: 総務省「地方公共団体の議会の議員及び長の所属党派別人員調」）
>
> **→ Polimoney の最大の差別化ポイントは「地方政治資金の可視化」にある。**

- 上記は叩き台。**自分の頭で「他にないか？」を考える**のが重要

## STEP 2: 「Polimoney が取り組むべき問題」を選ぶ

### やること

STEP 1 のリストに対し、以下の **3つの軸** でスコアリングし、優先順位をつける。

### 評価軸

| 軸                 | 問い                                                                                        | スコア        |
| ------------------ | ------------------------------------------------------------------------------------------- | ------------- |
| **①インパクト**    | この問題が解決されたら、どれくらいの人に、どれくらいの変化が起きるか？                      | 大 / 中 / 小  |
| **②Polimoney適性** | 「事実ベースで計算・表示する情報源」「問題を実感・発見できる場」として取り組める問題か？    | ◎ / ○ / △ / ✕ |
| **③実現可能性**    | 3プロダクト（Polimoney / Hub / Ledger）+ 発信活動（note / X）で、技術的・法的に実現可能か？ | 高 / 中 / 低  |

### 判断基準（前回合意との整合）

> **「直接解決するのではなく、問題を実感したり発見できる場をつくる」**

この原則に照らすと:

- ✅ 取り組むべき: データを見やすくする、比較できるようにする、気づきを与える
- ✅ 取り組むべき: 政治家の会計負荷を下げる（＝データ供給の質と量を上げる手段）
- ❌ 取り組まない: 政治家の行動を直接変える、政策提言する、議論の場を提供する

## STEP 3: 各問題へのアプローチを考える

### やること

STEP 2 で選んだ問題それぞれに対し、**「どうやって取り組むか」を1つ以上**考える。
各アプローチには、**どのプロダクト/活動が担うか**を明記する。

### アプローチの思考テンプレート

```text
問題:    [A-1] 収支報告書がPDFで公開されている（特に地方）
誰が困る: 市民、メディア、研究者
現状:    国政は2027年にDB化。地方は47選管のPDFのまま
2027年後: 国政は解消するが、地方（議員の9割超）は取り残される

アプローチ:
  (1) 47都道府県選管のPDFをクローリング+AI/OCRで構造化し、Hub に集約する
      → 担当: Hub（データ基盤）
  (2) 国政DB（総務省API）と地方データ（Hub独自）を統合して横断検索可能にする
      → 担当: Hub（API） + Polimoney（UI）
  (3) 地方議員向けに Ledger を提供し、入力時点でデータを構造化する
      → 担当: Ledger（データ供給の底上げ）

Polimoney の立ち位置:
  「国政は制度で解決される。地方の壁を壊すのが Polimoney の仕事」
```

### 問題ごとのアプローチ案（叩き台）

#### 「PDF問題」(A-1) + 「データ分散」(A-2) + 「フォーマット不統一」(A-7)

> [!IMPORTANT]
> **地方特化の戦略**: 国政データは2027年に総務省がDB公開するため、Polimoney が独自にスクレイピングする必要性は薄れる。
> **地方の約31,500人の議員（全体の9割超）のデータを構造化・横断検索可能にすること**が、
> 他のサービスにない Polimoney 独自の価値になる。

| アプローチ                                                        | 担当      | 具体イメージ                                                                             |
| ----------------------------------------------------------------- | --------- | ---------------------------------------------------------------------------------------- |
| 国政データは **総務省DBのAPI/データを活用**                       | Hub       | 2027年以降、自前スクレイピングから切り替え。コスト削減                                   |
| **47都道府県選管のPDFをクローリング** + AI/OCRで構造化            | Hub       | 選管ごとにフォーマットが異なるため、選管別のパーサーを開発。優先順位をつけて段階的に対応 |
| **地方データの統一スキーマ** を設計し、国政データと同じ構造で格納 | Hub       | 国政も地方も同じAPIで検索・比較できるようにする                                          |
| 統合データを検索・閲覧可能なUIで提供                              | Polimoney | 「住所を入れたら、国会議員も県議も市議もまとめて出る」                                   |

##### 地方データ取得の段階的アプローチ

```text
Phase 1: まず人口が多い都道府県から（東京・大阪・愛知・神奈川・…）
         → インパクトが大きく、データ量も豊富

Phase 2: 選管のPDF形式が似ている都道府県をグルーピングし、パーサーを流用

Phase 3: 残りの都道府県を順次対応

Phase 4: Ledger 利用者が増えれば、入力時点でデータが構造化される
         → スクレイピング不要な「正データ」が増える好循環
```

#### 「データが読み解けない」(D-2) + 「用語が難解」(A-5)

| アプローチ                                                 | 担当      | 具体イメージ                                                                                                          |
| ---------------------------------------------------------- | --------- | --------------------------------------------------------------------------------------------------------------------- |
| 収支を **サンキー図** で可視化し、お金の流れを直感的に表現 | Polimoney | 既存機能を強化。「人件費 40%」「広報 25%」のように比率で見せる                                                        |
| 金額に **比較の文脈** をつける                             | Polimoney | 「同じ選挙区の他候補と比較」「過去年との比較」「全国平均との比較」。**地方議員同士の比較は Polimoney でしかできない** |
| 費目名に **平易な説明** をツールチップで表示               | Polimoney | 「組織活動費」→「団体の運営にかかったお金（事務所費・人件費など）」                                                   |
| **要約テキスト** を自動生成                                | Polimoney | 「〇〇議員は2025年、収入の60%を個人献金から、支出の45%を人件費に使いました」                                          |

#### 「名寄せ」(A-6)

| アプローチ                                                         | 担当      | 具体イメージ                                                                |
| ------------------------------------------------------------------ | --------- | --------------------------------------------------------------------------- |
| 政治家IDで **複数団体を紐づけ**                                    | Hub       | 「山田太郎」→「山田太郎後援会」+「自民党〇〇支部」+「〇〇政経研究会」       |
| 紐づいた全団体の収支を **合算表示**                                | Polimoney | 政治家ページで「この人に関連する全資金」を一覧                              |
| **地方議員の名寄せ**は難易度が高い（同姓同名、団体名の表記揺れ等） | Hub       | 選挙データ（立候補者名簿）との突合で精度を上げる。Ledger 利用者は自動紐づけ |

#### 「報告書作成の手間」(B-1, B-2) + 「透明性アピール」(B-5)

> [!TIP]
> **地方議員こそ Ledger の最大のターゲット**。
> 国会議員は事務所スタッフやオンラインシステムがあるが、
> 地方議員は家族・ボランティア運営が多く、会計ツールのニーズが切実。
> **Ledger が地方に普及すれば、データの構造化問題（A-1）も同時に解決される。**

| アプローチ                                        | 担当               | 具体イメージ                                                                  |
| ------------------------------------------------- | ------------------ | ----------------------------------------------------------------------------- |
| **Ledger** で日常的に記帳 → 法定報告書を自動生成  | Ledger             | 地方議員の最大の痛み（紙+手作業+少人数）を解決。**「使うと楽になる」が hook** |
| **政務活動費と政治資金の分離管理** をLedgerで対応 | Ledger（※要議論） | 地方議員特有の「3つの財布」問題をUI/UXで防ぐ。**管理主体は11/7会議で確定**    |
| Ledger のデータを **Hub 経由で Polimoney に公開** | Hub → Polimoney    | 「公認バッジ付き」で信頼性を担保                                              |
| 公認バッジ付き政治家をランキング・特集            | Polimoney + note/X | 「透明性スコアが高い政治家」として広報                                        |

### 公職選挙法上の法的ガイドライン

> [!CAUTION]
> ### 絶対にやってはいけないこと
> 1. **「選挙に活用できる」「選挙で有利になる」等の表現**
>    - 公職選挙法上、「選挙運動」とは「特定の選挙で特定の候補者の当選を目的として投票を得させるための行為」（判例の定義）
>    - Polimoney / Ledger がこのような文脈で紹介されると、事前運動（[公選法129条](https://elaws.e-gov.go.jp/document?lawid=325AC1000000100)違反）の幇助と見なされるリスク
> 2. **告示日以降の新規アプローチ**
>    - 選挙期間中に政治家に「このツールを使いませんか」と連絡すると、選挙運動と誤解される
> 3. **特定候補者を有利/不利にする情報の偏った提示**
>    - 全候補者を一律・中立的に扱うことが必須
> 4. **投票日当日の新規コンテンツ投稿**
>    - 投票日当日の選挙運動は全面禁止（ネット含む、[総務省ガイドライン](https://www.soumu.go.jp/senkyo/senkyo_s/naruhodo/naruhodo10.html)参照）
> 5. **特定候補者への無償・過度な値引きでの Ledger 提供**
>    - **特定の候補者だけ** に無償提供する場合、公選法上の「寄附」や「買収」（[公選法221条](https://elaws.e-gov.go.jp/document?lawid=325AC1000000100)）とみなされるリスク
>    - **全候補者が一律に Web 上で登録・利用できるフリーミアムモデル** であれば、プラットフォームとしての中立的な提供にあたり、リスクは大幅に低い（選挙ドットコム等の先例と同様）
>    - ただし、有料プランを特定候補にだけ無料にする等の恣意的な運用は NG
>    - → **念のためリーガルチェックを推奨**

### Impact の定義（11/7 会議で議論すべき）

「統一地方選で Impact を出した」とは何を指すか？ 以下は議論のたたき台:

| Impact の指標 | 具体的な目標案 | 計測方法 |
|---|---|---|
| **データカバレッジ** | 対象エリアの現職議員の収支データを〇〇%カバー | Hub のデータ件数 |
| **ユーザー数** | 選挙前後にサイトのユニークユーザーが〇〇人を超える | アナリティクス |
| **メディア露出** | 〇件以上のメディアで引用・紹介される | クリッピング |

| **コントリビュータ** | 新規コントリビュータが〇人以上参加 | GitHub |
