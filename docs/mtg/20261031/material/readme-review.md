## 1. 方針のブレ・矛盾

### 1-1. 「コミュニケーションチャネル」か「監視ツール」か — ポジショニングが二重人格

| README の記述 | 統合仕様書の記述 | ブレ |
|---|---|---|
| 「政治家がどのような方向を目指しているかを伝えられるコミュニケーションチャネル」 | 「政治資金の透明化」「市民、研究者、メディア」向け | **政治家を"助ける"立ち位置** vs **市民が"監視する"立ち位置** が混在 |

> **問い**: Polimoney は誰の「味方」か？政治家に対して「あなたの資金の使い方を市民に魅力的に伝えましょう」なのか、市民に対して「政治家が何に使っているか調べましょう」なのか。**両立を目指すなら、README 冒頭で明示的に "双方向の価値" として構造化すべき**。

### 1-2. 「政治資金の問題がなくなる2030年」— ゴールが曖昧

- 「問題がなくなる」とは何を指すのか未定義
  - 不正がなくなる？ → Polimoney 単体では無理
  - 議会で政治資金の問題が繰り返し議論される時間が減る？ → それならKPIを書くべき
  - 政治資金の **不透明さ** がなくなる？ → こちらなら具体化可能
- **提案**: 「2030年までに、すべての国政候補者の政治資金情報が Polimoney 上でリアルタイムに参照可能な状態」のように、検証可能なゴール文にする

### 1-3. 「複式簿記で透明化できる！ではなく」— 何を言いたいのか不明

> 「単式簿記ではなく、複式簿記でシステムを動かすこと透明化できる！ではなく・・・透明化を目指してます！というロードマップとして伝える」

- 文が壊れている。内部メモがそのまま残っている印象
- **複式簿記と透明化の関係** を明確に説明する必要がある（例: 「複式簿記により資金の出所と使途を対応付けて追跡可能にする。ただし現行の法制度上、報告書は単式であるため、まずはデータの可視化から始め、段階的に会計精度を上げる」）

## 4. インセンティブ設計の欠如

### 4-1. 各ユーザーが「使い続ける理由」が書かれていない

| ユーザー | なぜ来るか（初回） | なぜ続けるか（定着）← **ここが空白** |
|---|---|---|
| 一般市民 | SNS で話題 / 選挙前 | ❌ 定期的に見る理由がない。更新通知？フォロー機能？ |
| メディア | 調査のため | ❌ データが最新でなければ使わない。更新頻度のSLAは？ |
| 政治家 | 透明性アピール | ❌ 入力の手間 > メリット、という認識になりやすい。実際に使ってもらうインセンティブは？ |
| 支援者 | 推しの応援 | ❌ 寄付機能がないうちは他のプラットフォームで十分 |

### 4-2. 提案: インセンティブを明文化

**一般市民向け:**
- 選挙区の議員に変化があったら通知（プッシュ or メール）
- 「あなたの街の政治家ランキング（透明度スコア）」
- SNS シェア時のOGP画像自動生成（「〇〇議員の資金使途」）

**政治家向け（最も重要 — データ供給側）:**
- **Ledger を使えば法定報告書の作成コストが下がる** ← これが最大の hook
- 公認バッジにより「透明性が高い政治家」としてのブランディング
- Polimoney 上での政治家ページが実質的な公式プロフィールになる

**メディア向け:**
- APIドキュメント、データスキーマの公開
- 引用元としての Polimoney クレジット → プロジェクトの知名度向上
